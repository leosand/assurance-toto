# keychain.md — NIP-49 Key Backup

The keys generated by `npm run init-buzz-keys` are written to `.env.buzz` (mode `600`, gitignored). **Never** commit them.

## Recommended backup (NIP-49)

Each individual `nsec` can be encrypted client-side with a strong passphrase (NIP-49, `ncryptsec1…` scheme):

```ts
import { generateSecretKey } from 'nostr-tools/pure';
import * as nip49 from 'nostr-tools/nip49';

const sk = generateSecretKey();
const ncryptsec = nip49.encrypt(sk, '<strong-random-passphrase>');
// → store this `ncryptsec1…` in a vault (Bitwarden / 1Password), not `.env.buzz`.
```

Rules:

- 1 master passphrase per environment (dev / staging / prod), stored in a team vault, NOT in the repo.
- The `.env.buzz` file = operational source of truth **locally only**. Any rotation regenerates the file (never edit it), and each `ncryptsec` is re-imported.
- Npubs are public: no secrets in the `BRIDGE_CEOPUBKEYS` mapping.
- An exposed `nsec` ⇒ full key-pair rotation + purge of the RBAC map (`BRIDGE_CEOPUBKEYS`) + invalidation of the associated commands.

## CEO vs agent needs

- CEO npub → `BRIDGE_CEOPUBKEYS` (csv): the only role that can approve `claim.settlement.*`, `policy.pricing.exception.*`, `agent.killswitch.*`.
- Agents (sales / souscription / sinistres / finance / conformité / hermes): their npubs only need their own nsec to produce signed events; they cannot grant themselves a CEO-reserved decision.

## Do not

- No cleartext nsec in code, logs, issues, Slack, or a commit.
- No nsec on a non-isolated CI — rotation would be impossible without a full audit.
